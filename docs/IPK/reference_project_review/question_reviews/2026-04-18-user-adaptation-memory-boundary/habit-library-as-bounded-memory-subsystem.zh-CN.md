# 习惯库作为有边界的记忆子系统：讨论结论

> 状态：已拍板  
> 来源：基于本轮“用户自适应系统与记忆系统是否合并”的后续讨论整理  
> 核心结论：习惯库可以属于长期记忆体系，但不能变成普通记忆池里的普通条目。

## 第一部分：短版结论

### 1. 总结论

用户自适应来自记忆，但不是普通记忆。

更准确的结构是：

```text
普通记忆负责“记住发生过什么”。
稳定用户画像负责“总结用户长期是谁”。
当前状态摘要负责“总结用户现在处于什么状态”。
长期习惯库负责“决定以后跨会话默认怎么做”。
短期习惯/scratch 负责“当前会话或当前任务先临时怎么做”。
context compiler 负责“本轮到底拿哪些东西出来用”。
```

### 2. 习惯库可以属于记忆体系，但必须有明显边界

习惯库应是长期记忆体系里的强治理子系统。

它可以和普通记忆共用存储底座、索引、备份和证据链，但不能和普通记忆混成一个无边界池子。

### 3. 普通记忆会影响回答，但不一定要变成习惯

“用户昨天读了某篇论文”“用户最近学到旋量场量子化”都会影响回答。

但它们首先是近期学习状态、用户知识坐标或任务背景，不一定是长期正式习惯。

### 4. 普通记忆先进入当前状态或候选证据，稳定画像是后续沉淀结果

更稳的路径是：

```text
普通记忆
  -> 当前状态摘要 / 候选证据
  -> 长期习惯候选
  -> 用户确认或长期稳定判断
  -> 长期习惯库 / 稳定用户画像
```

普通记忆不应直接写入稳定用户画像或长期习惯库。

### 5. 长期习惯是 ready-to-use 的行为规则，短期习惯先进 scratch

普通记忆是被动等待检索。

长期习惯不同，它要在合适场景里随时 ready，主动指导 AI 的回答和行动。

当前会话或当前任务里的临时要求，可以先成为短期习惯/scratch habit，立即在本轮或本 session 生效，但不自动进入长期习惯库。

### 6. 长期习惯需要反复揣摩和治理

记忆“存在过”就可以先存着。

长期习惯会改变未来默认行为，所以需要作用域判断、冲突处理、反复校准和必要的用户确认。

### 7. 用户要求引用外部文件时，习惯应保存规则，内容应保存引用

例子：

```text
用户要求：以后用某个文件里的符号系统回答 QFT 问题。
习惯规则：回答 QFT 时优先使用该文件的符号系统。
外部引用：那个文件 / artifact contract / IPK piece。
```

这里用户要求是习惯证据，文件内容是被引用的外部真源。

### 8. assistant 输出不能单独证明用户习惯，但可以成为被确认的规则内容或引用材料

assistant 的总结、解释、工具结果可以成为普通记忆或被引用材料。

它不能单独证明“用户长期偏好就是这样”。

但如果用户明确要求、确认、认可或引用了 assistant 输出，那么 assistant 输出可以成为习惯规则内容、外部引用材料或被确认的派生材料。

### 9. 最推荐的层次结构

```text
原始记忆层
稳定用户画像层
当前状态摘要层
长期习惯候选层
短期习惯/scratch 层
长期习惯库
运行时 context compiler
```

这些层强相关，但职责不同。

### 10. 对 Aether 的最终方向

Aether 应采用：

```text
统一长期记忆底座
+ 有边界的长期习惯库子系统
+ 按需召回的普通记忆
+ 随时 ready 的当前习惯集合
+ 运行时统一编排
```

这能同时保留记忆的宽度和习惯的可靠性。

## 第二部分：详细说明

### 1. 总结论

“用户自适应是记忆的一种应用”这句话总体成立，但不能停在这里。

用户自适应和普通记忆的差别不在于“是不是过去信息”，而在于“是否会改变未来默认行为，或当前 session 的即时行为”。

普通记忆更像档案：它记录用户读过什么、问过什么、做过什么、在哪个任务中遇到过什么。

稳定用户画像更像长期摘要：它把这些档案压缩成“用户长期是谁、熟悉什么、偏好什么、通常怎样协作”。

当前状态摘要更像短中期摘要：它总结“用户最近在学什么、正在关注什么、当前理解到哪里、当前任务推进到哪一步”。

长期习惯库更像行为规则库：它告诉 AI 在未来类似场景中应该默认怎样回答、怎样工作、怎样协作。

短期习惯/scratch 则更像当前 session 的临时规则：它可以马上生效，但默认不跨会话。

所以，最终结构不应该只是：

```text
记忆 = 用户自适应
```

而应该是：

```text
记忆提供材料。
画像/状态提供当前理解。
长期习惯库提供跨会话行为规则。
短期习惯/scratch 提供当前 session 行为规则。
context compiler 在本轮把它们组合起来。
```

### 2. 习惯库可以属于记忆体系，但必须有明显边界

习惯库不必和记忆系统完全分家。

它可以放在同一个长期记忆根目录下，也可以共用：

- 路径解析；
- 权限校验；
- 备份和迁移；
- provenance；
- 索引重建；
- 证据引用；
- 删除、撤销和审计的基础设施。

但它不能变成普通记忆库里的普通条目。

原因是普通记忆和习惯的运行后果不同。普通记忆被错误召回时，通常只影响一次回答；习惯如果被错误写入，会长期改变系统对用户的默认理解和行动方式。

因此，习惯库应该是长期记忆体系里的一个强类型、强治理、强边界子系统。

推荐表达是：

```text
习惯库属于 memory family。
习惯库不属于 generic memory pool。
```

### 3. 普通记忆会影响回答，但不一定要变成习惯

之前用“用户昨天读了某篇论文”作为普通记忆例子时，需要补充一点：这类信息确实可能影响回答。

例如：

- 用户昨天读了某篇论文，今天问相关问题时，可以优先用那篇论文里的例子。
- 用户最近在学量子场论，并且学到旋量场量子化，回答 QFT 问题时就可以接在这个理解进度上。
- 用户最近一直在整理某个研究计划，相关问题就应该优先连接那个计划背景。

这些信息不只是“冷冰冰的历史事实”。它们会影响系统当下怎样解释、选例子、判断用户可能知道什么。

但它们仍然不一定是习惯。

更准确地说，它们可能属于：

- 近期学习状态；
- subject profile；
- task context；
- session recall；
- IPK 或文件引用；
- 普通长期记忆。

只有当这类信息变成“以后跨会话、跨类似场景中应该默认这样帮助用户”的规则时，才应该进入长期习惯库。

如果用户只是在当前对话里说“这轮先按这篇论文的符号和例子来”，它可以成为短期习惯/scratch habit，马上影响当前 session，但不应自动升级为长期习惯。

### 4. 普通记忆先进入当前状态或候选证据，稳定画像是后续沉淀结果

从普通记忆到习惯库，中间应该有缓冲层。

不推荐：

```text
普通记忆 -> 直接变成习惯
```

推荐：

```text
普通记忆
  -> 当前状态摘要 / 候选证据
  -> 长期习惯候选
  -> 用户确认或稳定性判断
  -> 长期习惯库 / 稳定用户画像
```

例子：

```text
普通记忆：用户最近多次讨论旋量场量子化。
当前状态摘要：用户正在学习 QFT 的旋量场部分。
长期习惯候选：讲 QFT 时可以连接用户当前学习进度。
长期习惯库：如果用户确认或长期重复，再写入对应 subject/task_scope 习惯。
```

这个缓冲层很重要，因为很多记忆只适合影响当下回答，不适合改变长期默认行为。

稳定用户画像也不应该被普通记忆直接改写。它应该是后续沉淀结果：只有当某类信息长期稳定、跨场景反复出现，或被用户明确确认代表自己，才进入稳定用户画像。

换句话说：

```text
普通记忆可以参与本轮 context。
普通记忆可以更新当前状态摘要。
普通记忆也可以产生长期习惯候选。
普通记忆也可以触发当前 session 的短期习惯/scratch。
普通记忆不应直接写入稳定用户画像。
但普通记忆不应自动等于长期正式习惯。
```

### 5. 长期习惯是 ready-to-use 的行为规则，短期习惯先进 scratch

普通记忆和长期习惯最大的运行时差别是：

```text
普通记忆：被动等待查找。
长期习惯：在合适场景主动 ready。
短期习惯/scratch：在当前 session 或当前任务主动 ready。
```

普通记忆可以很多、很杂、很宽。它可以记录一次阅读、一段会话、一个旧任务、一条工具输出、一个历史事实。

长期习惯必须少一些、稳一些、可解释一些。它要能在上下文编译时被快速判断：

- 是否适用于当前问题；
- 是否应主动注入；
- 是否和当前用户要求冲突；
- 是否和其它习惯冲突；
- 是否应该被降权、替换或收窄作用域。

所以长期习惯不是“多存一点记忆”。

长期习惯是系统跨会话随时准备使用的行为控制材料。

短期习惯/scratch 也是行为控制材料，但它的默认边界更窄：

- 只服务当前 session、当前任务或当前用户临时要求；
- 可以立即生效；
- 可以和长期习惯冲突，并在当前 session 中临时遮蔽长期习惯；
- 只有被用户确认、长期重复或经过 promotion，才进入长期习惯库。

### 6. 长期习惯需要反复揣摩和治理

普通记忆的核心判断可以比较宽松：

```text
这件事是否发生过？
是否值得以后可能查到？
来源是什么？
```

长期习惯的核心判断更严格：

```text
这是否真的代表用户长期偏好？
适用于哪个作用域？
是否只是当前 session 的短期习惯/scratch？
是否会错误影响未来回答？
是否需要用户确认？
是否与旧习惯冲突？
```

这也是为什么“记忆有就是有”，但“长期习惯要反复揣摩”。

习惯库应该支持：

- session scratch；
- habit candidate；
- proposal；
- promotion；
- rescope；
- conflict；
- suppression；
- tombstone 或撤销；
- 用户确认；
- 证据追溯。

这些治理机制不是额外复杂化，而是因为长期习惯一旦生效，就会持续影响 AI 的行为。

短期习惯/scratch 的治理重点不同：它更重视当前 session 的即时尊重、冲突遮蔽和退出机制；只有当它要升级为长期习惯时，才进入更严格的长期治理。

### 7. 用户要求引用外部文件时，习惯应保存规则，内容应保存引用

一个重要边界情况是：用户明确提出了行为要求，但要求的具体内容在外部文件里。

例如：

```text
用户：以后回答量子场论问题时，用这个文件里的符号系统。
```

这个时候，只看用户消息会不够，因为用户没有在消息中展开完整符号系统。

但也不能因此把 assistant 对文件的总结直接当成用户习惯。

更稳的做法是把它拆成三部分：

```text
习惯规则：
回答 QFT 问题时，优先使用某文件中的符号系统。

习惯证据：
用户明确提出了这个要求。

外部真源：
被引用的文件、artifact contract、IPK piece 或 symbol table。
```

运行时命中这条习惯时，context compiler 再去读取或引用对应文件的符号摘要。

这样既不会丢失具体符号系统，也不会让 assistant 自己的解释污染用户习惯真源。

### 8. assistant 输出不能单独证明用户习惯，但可以成为被确认的规则内容或引用材料

assistant 输出并不是永远不能进入长期系统。

它可以进入：

- session summary；
- task memory；
- agent experience；
- tool result memory；
- 普通长期记忆；
- 被用户明确认可的材料引用；
- IPK 草稿或候选内容。

但它不应该单独成为“用户长期正式习惯”的证据。

这里要区分两件事：

```text
用户意图证据：用户是否真的要求以后这样做。
规则内容材料：以后要用的具体内容、符号、格式、定义或总结来自哪里。
```

长期习惯的用户意图证据应该优先来自：

- 用户明确表达；
- 用户反复行为；
- 用户确认；
- 用户对 assistant 输出的认可或修正；
- 用户明确指定的外部文件或知识对象。

assistant 输出可以在这些情况下进入习惯相关链路：

- 用户明确说“以后就按你刚才这套说法/符号/格式来”；
- 用户要求使用某个文件，assistant 读取后生成了符号表或摘要；
- 用户确认 assistant 对某个长期偏好的总结是准确的；
- assistant 输出被保存为 artifact / IPK piece / symbol table，并被习惯规则引用。

因此，更准确的规则是：

```text
assistant 输出不能单独证明用户习惯。
assistant 输出可以在用户要求、确认或引用后，成为习惯规则内容或外部材料。
```

这条边界能同时保留普通记忆的宽度和习惯库的可信度。

### 9. 最推荐的层次结构

推荐把系统理解为七层。

第一层是原始记忆层。

它保存发生过什么，包括会话、阅读、任务、工具结果、文件、总结、历史事实等。

第二层是稳定用户画像层。

它从原始记忆中总结用户长期相对稳定的信息，例如长期研究方向、熟悉的学科、协作偏好、表达偏好和重要背景。

第三层是当前状态摘要层。

它总结短中期状态，例如最近在学什么、当前任务推进到哪里、最近读了哪些材料、当前理解边界在哪里。

第四层是长期习惯候选层。

它提出“以后可能应该这样帮助用户”的候选规则，但还没有成为长期默认行为。

第五层是短期习惯/scratch 层。

它保存当前 session 或当前任务中已经明确、需要马上尊重的临时行为规则。它可以立即生效，但默认不跨会话。

第六层是长期习惯库。

它保存已经确认、稳定或经过治理的 ready-to-use 跨会话行为规则。

第七层是运行时 context compiler。

它在每轮请求里决定：

- 哪些稳定用户信息要带上；
- 哪些当前 session 习惯要带上；
- 哪些 scratch 要带上；
- 哪些普通记忆需要按需召回；
- 哪些 IPK 或文件引用需要进入上下文；
- 哪些 pending proposal 不能直接生效。

这些层不是孤岛，而是一个有边界的流水线。

### 10. 对 Aether 的最终方向

对 Aether 来说，最稳路线不是“完全合并”，也不是“完全分立”。

推荐结构是：

```text
统一长期记忆底座
  - IPK
  - 普通长期记忆
  - session recall
  - 稳定用户画像
  - 当前状态摘要
  - 有边界的长期习惯库

运行时统一编排
  - 稳定用户层
  - 当前 session active habits
  - scratch habits
  - 按需召回 memory
  - IPK / artifact references
```

其中，习惯库的位置应该是：

```text
长期记忆体系中的有边界子系统。
```

长期习惯库持续从普通记忆、稳定画像、当前状态摘要和短期习惯/scratch 中得到材料，生成候选，接受审阅，并更新自身。

但它始终保留更严格的进入门槛、更清楚的作用域、更强的审计和更稳定的运行时地位。

最终一句话：

> 记忆让系统知道用户经历过什么；稳定画像让系统知道用户长期是谁；当前状态摘要让系统知道用户现在处于什么状态；短期习惯让系统知道当前 session 先怎么做；长期习惯库让系统知道以后跨会话默认应该怎样帮助用户。
